# Contributing

1. Create a short feature branch from `main`.
2. Keep pull requests focused on one requirement or architectural concern.
3. Do not commit secrets, personal health data, production exports, or participant evidence.
4. Run `npm run check` and Python compilation checks before opening a pull request.
5. Explain privacy, consent, accessibility, and security effects in the pull request.
6. Obtain review and pass required CI checks before merging.
